# 기능 의도 기록

기능마다 무엇을 왜 만들고 어떤 조건에서 완료로 판단할지 코드와 함께 보관한다. [Claude Academy의 Capture as intent.md](https://academy.claude.com/courses/ai-native-sdlc-playbook/capture-intent)를 이 저장소에 적용한 절차다.

## 작성과 개발

1. 기능 추가 또는 사용자 동작 변경 요청을 받으면 관련 intent를 찾는다. 같은 목적의 후속 수정은 기존 파일을 갱신하고 독립 기능은 새 파일을 만든다.
2. 구현 전에 [템플릿](_template.md)을 `YYYY-MM-DD-short-feature-name.md`로 복사한다. 같은 날 이름이 겹치면 의미 있는 접미사를 붙인다. 요청자의 표현을 바탕으로 문제·기대 결과·범위·제약·관찰 가능한 수용 기준을 채운다. 작은 기능은 각 항목을 한두 문장으로 작성한다.
3. 요청으로 확정된 내용과 구현자가 둔 가정을 구분한다. 결과나 범위를 바꿀 미해결 질문은 요청자에게 확인하고, 그 답이 필요한 구현은 답변 후 진행한다. 그 외에는 가정을 기록하고 이미 요청받은 범위 안에서 진행한다.
4. 작성자가 검토·수정할 수 있도록 intent 경로와 주요 해석을 공유한다. 검토란에는 실제 확인된 검토만 기록한다. 커밋 전 요청자/제품 책임자가 검토할 수 있게 제시하고, 검토가 확인되기 전까지는 미검토로 유지한다. 문서 작성 자체를 별도 승인 절차로 삼지 않는다.
5. 구현 중 범위나 수용 기준이 바뀌면 intent도 함께 고친다. 완료 시 각 기준의 실제 검증 결과, 미확인 항목, 관련 코드·문서 경로를 기록한다. 기준을 모두 충족하면 `완료`, 작업이 남으면 `진행 중`으로 둔다. 채택하지 않은 의도는 이유와 함께 `보류`로 보존한다.
6. intent를 관련 코드와 같은 변경에 포함한다. 커밋·PR을 만들 때 intent 경로를 연결하고 AGENTS.md의 프로젝트 문서 갱신 규칙을 따른다. 작성자·시각·수정 이력은 문서 메타데이터와 Git 이력으로 추적한다.

## 적용 범위

- 신규 기능과 기존 기능의 사용자 동작 변경은 기능별 intent를 남긴다.
- 동작을 바꾸지 않는 리팩터링·오탈자·정기 데이터 갱신은 새 intent 없이 기존 작업 기록을 사용한다. 기존 기능 의도와 관련된 수정은 해당 intent에 연결한다.
- 과거 기능을 한꺼번에 소급 작성하지 않는다. 이후 변경하는 기능부터 적용한다.
- intent는 변경의 목적과 완료 조건을 담는다. 현재 제품 요구사항은 `srs.md`, 구조는 `architecture.md`, 전체 진행 기록은 `project_plan.md`를 기준으로 하며 필요한 곳을 링크한다.

상태: `초안` → `진행 중` → `완료`, 또는 `보류`. 검토 여부는 작업 상태와 별도로 기록한다.
