# Intent: 명확한 견적 요청은 바로 계산

- 작성일: 2026-11-11
- 작성자: Codex
- 요청자: 사용자
- 상태: 완료
- 요청자/제품 책임자 검토: 미검토

## 문제와 기대 결과
명확한 요청도 EXAONE 해석을 기다려 중앙값 22초가 추가된다. 용도와 예산을 규칙 또는 명시한 UI 조건으로 알 수 있으면 모델 없이 견적을 계산하고, 모호한 요청만 EXAONE으로 보완한다.

## 범위와 제약
화면은 명확한 요청에서 해석 API 자체를 생략하고 서버도 같은 텍스트 기준으로 모델 호출을 생략한다. 알려진 용도 + 금액 또는 명시적 무제한을 명확한 요청으로 판단한다. UI에서 직접 선택한 용도·예산도 반영한다. 추가 요청은 문맥으로 판별한다. 예산 미지정·새 용도로 전환·미인식 용도는 기존 모델 보완과 안전한 확인 경로를 유지한다. 명시 조건, 상대 예산 증감, 무제한 및 실패 안전성은 유지한다.

## 수용 기준
- [x] 명확한 요청은 화면 해석 API 0회, 서버 모델 0회이며 규칙 기반으로 표시한다.
- [x] 용도 미인식·예산 미지정 요청은 모델을 호출한다.
- [x] 후속 증액·옵션·무제한 및 수동 조건 지정도 정확히 반영한다.
- [x] 실패 시 용도 질문, 명시 조건 보호, 기존 견적 검사 회귀가 통과한다.
- [x] 실제 API에서 빠른 경로 시간과 모호한 요청의 EXAONE 경로를 확인하고 서버에 반영한다.

## 가정과 열린 질문
- 금액이 없는 요청의 기존 무상한 견적 정책은 유지하지만 명확한 예산으로 간주하지 않아 모델 보완 대상으로 둔다.
- 질문: 없음.

## 구현 및 검증 결과
- 화면 canInterpretLocally / 서버 can_interpret_locally 적용. 명확한 요청은 method=local로 바로 계산, 모호한 요청만 모델 호출. 최종 requestBudget을 분기와 추천 입력이 공유한다. 연출용 600ms 대기 제거.
- 수정 전 명확한 입력 Python 5개 및 UI API 0회 검사 실패를 확인한 뒤 통과. “예산은 제한 없이” 추가 실패도 재현 후 양쪽 표현 인식 수정.
- 최종 백엔드 284개·화면 95개·빌드·diff 검사 통과. 수동 선택·추가 증액·무제한·옵션·모델 보완·실패 안전성 검사 포함.
- 서버 반영. 실제 명확한 API 5개 중앙 약 1.10ms, 모호한 W002 EXAONE/gaming/14.72초. UI는 명확한 요청의 해석 API 자체를 호출하지 않음.
- 같은 50개·55턴·150안 재평가 PASS 49/WARN 1/FAIL 0. 배치에서 53턴 규칙·2턴 EXAONE이었으며, 그중 조사 포함 무제한 W020을 보완 후 API로 재시험(local·무상한·3안 PASS). 최종 55문장 분기는 양쪽 모두 규칙 54·EXAONE 1.
- [상세 기록](../../pcquote/docs/evaluations/2026-11-11-selective-exaone.md). srs·양쪽 구조 문서 갱신.
- 남은 범위: 실시간 가격/재고·FPS·브라우저 직접 조작·표현 보완 후 전체 50개 재실행은 미실행. 기록된 새 카탈로그와 이전 카탈로그가 달라 전체 소요시간의 엄밀한 속도 배수 비교는 하지 않음. 요청자 검토 미검토 유지.
