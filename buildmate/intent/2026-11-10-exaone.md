## 문제와 기대 결과
OpenRouter 대신 사용자가 제공한 EXAONE 키로 K-EXAONE 2.5를 직접 호출한다. 요구 해석과 근거 기반 답변, 평가 스크립트가 같은 설정을 사용한다.

## 범위와 제약
키는 git에서 제외된 서버 .env에만 저장한다. EXAONE 실패 시 OpenRouter로 전송하지 않고 기존 규칙 대체를 유지한다. EXAONE 공식 API의 low 추론과 JSON 출력 지시를 사용하고 기존 결과 검증을 유지한다. 기존 OpenRouter 설정 호환은 보존한다.

## 수용 기준

- [x] 실제 키로 요구 해석과 상담 답변을 성공한다.
- [x] 전송·오류 대체 회귀 검사가 통과한다.
- [x] 로컬 실행 서버에 설정을 반영한다.

## 가정과 열린 질문
- 가정: 모델은 제공된 문서의 k-exaone_v2.5이다.
- 질문: 없음.

## 구현 및 검증 결과
- 서버와 두 평가 도구는 configured_llm으로 같은 EXAONE 설정을 사용한다. backend/.env는 git 제외 및 권한 600 확인.
- 실제 서버 /api/requirements: method=exaone, 게임·150만원·QHD 유지(29.9초). /api/answer: HTTP 200, method=llm, rounds=1 한국어 답변 확인.
- 전체 백엔드 270개·화면 88개·Vite 빌드 통과. JSON 지시 통합 뒤 전체 270개 통과, 선행 공백 제거 수정 뒤 제공자 테스트 6개 통과. diff 공백 검사 통과.
- 8001 실행 서버를 최종 코드로 재시작하고 health 정상·상담 답변 확인.
- 초기 HTTP 429 및 일부 JSON 형식 실패를 관측. JSON 시스템 지시 통합·공백/코드펜스 처리 보강 후 실제 상담 성공. 한도 오류 시 규칙 대체 유지.
- 남은 항목: 대규모 실제 모델 평가·브라우저 직접 조작은 미실행. 요청자 검토는 미검토 유지.
