## 문제와 기대 결과
사용자는 해상도·Wi-Fi·OS의 “확정 전 확인해 주세요” 패널이 필요 없고 시간을 소모한다고 지적했다. 선택 정보가 없어도 기존 기본값으로 바로 견적을 보여 준다.

## 범위와 제약
확인 패널 및 화면의 선택 질문 상태·저장을 제거하고 모델도 선택 질문을 만들지 않도록 한다. 서버의 정상 모델 해석 결과는 questions=[]로 정리한다. 용도 자체를 알 수 없어 견적을 만들 수 없는 경우에는 기존 안전 동작을 유지하고 대화 메시지에서 용도를 직접 묻는다. 선택 옵션 입력과 후속 변경은 유지한다.

## 수용 기준
- [x] 새/복원된 선택 질문은 패널로 표시되지 않는다.
- [x] 정상 모델 응답에 선택 질문이 있어도 서버는 빈 목록으로 반환하고 견적을 바로 표시한다.
- [x] 용도 미확인은 견적을 생성하지 않고 대화에서 용도를 묻고, 답변 후 원래 조건으로 재개한다.
- [x] 관련 회귀 검사 및 빌드 통과, 실행 환경에 반영한다.

## 구현 및 검증 결과
- 선택 질문 패널·전용 CSS·questions 화면 상태 및 저장 필드를 제거. 복원된 질문도 표시하지 않음. 옵션 입력은 그대로 사용한다.
- 모델 프롬프트에서 선택 질문 생성 금지, 요청 스키마 maxItems=0. 정상 interpret 결과는 questions=[]로 정리해 모델이 질문을 반환해도 전달하지 않는다.
- needsPurpose는 기존처럼 견적을 막되, 용도 질문을 assistant 대화 메시지로 직접 표시. 입력창도 용도 안내를 제공하며 답변 후 기존 예산으로 재개한다.
