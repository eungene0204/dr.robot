## 문제와 이유
EXAONE 요청은 최대 두 번 60초를 기다리지만 화면은 45초에 중단한다. 모델 사용 불가 시 규칙에 없는 LaTeX 작업을 gaming으로 가정해 잘못된 부품을 추천한다.

## 기대 결과와 범위
화면은 서버가 안내하는 요구 해석 대기 시간을 적용한다. 용도를 알 수 없으면 견적 대신 질문을 표시하고, 답을 받으면 원래 예산·옵션을 이어 받아 견적을 만든다. 화면의 자동 기본값이 정상 LLM 용도 해석을 덮어쓰지 않게 한다. 서버도 미확인 요청의 추천을 막는다.

## 제약
문장에 명시한 용도·예산·해상도 보호, 알려진 용도의 오류 시 규칙 견적은 유지한다. 키는 노출하지 않는다. 기존 평가 자료와 로컬 실행 데이터를 보존한다.

## 수용 기준
- [x] 55초 뒤 정상 해석을 반환하는 요청이 화면에서 45초 때문에 중단되지 않는다.
- [x] LLM 오류·미설정 및 용도 불명 요청은 needsPurpose를 반환하고 추천을 막는다.
- [x] 화면은 용도를 묻고, 후속 답변 또는 수동 용도 선택으로 원래 예산·옵션을 유지해 재개한다.
- [x] 규칙에 없는 LaTeX를 LLM이 office로 해석하면 화면도 office/FHD로 생성한다.
- [x] 회귀 검사와 실제 EXAONE 사례 재시험, 실행 서버 반영을 완료한다.

## 구현 및 검증 결과
- 수정 전 회귀: pytest unknown_purpose/pending_purpose 3개 실패, UI EXAONE 3개 실패를 확인. 서버의 게임용 기본값, 정상 모델 office/FHD를 덮는 화면 자동값, 45초 중단을 각각 재현했다. 이후 모두 통과.
- EXAONE 읽기 60초·연결/쓰기/풀 각 5초·요구 해석 2회 정책을 상수로 관리하고 health에 requirementsTimeoutMs=160000을 공개. 화면이 이를 사용하고, fetch 자체 실패도 알려진 용도 규칙/미확인 질문으로 처리한다. 55초 가상 시간의 응답을 받는 UI 검사 통과.
- _local은 미확인 용도에 profile=null·needsPurpose=true를 반환. API 추천과 screen.to_request 차단. UI는 견적을 만들지 않고 질문한 뒤 기존 req 문장·예산·옵션으로 재개한다. 후속 사무 답변 및 수동 사무 선택에서 예산 150만원·화이트·와이파이 보존 검증.
- 자동 입력은 판별한 값만 채우고 LLM이 보완한 용도를 보존. office의 미지정 해상도는 FHD로 정하되 명시 QHD는 유지한다.
- 최종 검증: 백엔드 276개·화면 93개·Vite 빌드·diff 공백 검사 통과. 임시 DEBUG 계측 없음.
- 실행 서버 최종 코드로 재시작, health 정책 값 확인. 실제 /api/requirements의 LaTeX 원문을 EXAONE이 office/FHD/150만원으로 31.33초에 해석. 저장 카탈로그로 생성한 사무용 3안 1,264,410원 / 1,491,910원 / 969,260원, 전 안 CPU 내장 그래픽·예산 이내·호환 검사 통과.
- 실제 호출 원본: pcquote/reports/quote-eval/20261111-021250-exaone-fixed-live.json(Git 제외). 당시 실패 자료는 기존 평가 보고서에 보존하고 수정 결과를 덧붙였다.
- 남은 검증 범위: 대규모 실제 모델 55개 전체 재평가·실시간 가격/재고·브라우저 직접 조작은 이번 수정에서 미실행. UI는 JSDOM 회귀 검사, 실제 모델은 실행 API로 검증했다. 요청자 검토는 미검토 유지.
