# 문제 해결 기록

버그·오류·성능 저하·운영 장애를 다룰 때마다 이 문서에 기록한다. 작은 문제는 각 항목을 한 문장으로 채워도 된다.

## 기록 절차

1. 조사 전에 증상·오류 메시지·관련 모듈로 기존 기록을 검색해 이전 원인과 해결 방법을 확인한다.
2. 새 문제는 아래 템플릿을 복사해 문서 끝에 추가한다. ID는 `YYYY-MM-DD-short-name`으로 정하고 문서 내에서 고유하게 유지한다.
3. 작업 종료 전에 증상·원인·해결 방법·재발 방지·검증을 채운다. 확인한 원인에는 재현·로그·코드 등 근거를 붙이고 추정은 가설로 표시한다. 원인을 모르면 `미확인`으로 기록한다.
4. 수정 후 원래 재현 조건으로 확인한 결과와 실제 실행한 명령·테스트를 기록한다. 재현하지 못했거나 검증하지 않은 부분은 `미확인`으로 남긴다. 비밀키·고객 개인정보는 제거한다.
5. 재발 방지에는 적용한 회귀 테스트·검증 규칙·모니터링·운영 절차와 그 경로를 적는다. 추가 조치가 필요하면 체크박스로 남기고, 조치가 불필요하면 이유를 쓴다. 효과를 확인하지 않았으면 미확인으로 표시한다.
6. 관련 코드와 같은 변경에 기록을 포함하고 project_plan.md에 기록 앵커 링크와 요약을 남긴다. 기능 의도와 연결되면 해당 intent도 링크한다. 같은 문제가 재발하면 새 날짜의 기록을 추가해 이전 기록과 연결하고, 기존 조치가 막지 못한 이유를 적는다.

상태는 `조사 중`, `임시 조치`, `해결` 중 하나를 사용한다. 원인이 확인되고 수정 후 원래 증상의 해소를 검증했을 때 `해결`로 표시한다. 재발 방지의 남은 조치와 장기 효과 확인 여부는 별도로 남긴다.

### 2026-11-06-amd-only-recommendations — 추천 견적이 모두 AMD CPU로만 구성됨

- 날짜: 2026-11-06
- 상태: 임시 조치 (파서 수정 완료, Intel 보드 BIOS 지원 목록 등록은 제조사 근거 확보 대기)
- 관련 경로: [pipeline/adapters/danawa.mjs](pipeline/adapters/danawa.mjs), [pipeline/config/reviews.json](pipeline/config/reviews.json), [src/compatibility.mjs](src/compatibility.mjs), [tests/pipeline.test.mjs](tests/pipeline.test.mjs)

#### 증상
- 발생 환경·입력·재현 순서: `public/data/catalog.json` 스냅샷(가격·벤치 관측 시각을 현재로 가정)으로 게임 150/250/350만원, 영상편집 300만원 요청을 실행.
- 기대 동작 / 실제 동작·오류: Intel·AMD 중 조건에 맞는 CPU가 섞여 제안되기를 기대했지만, 세 안 모두 AMD Ryzen(7500F·9600X·9700X·9800X3D·9950X3D)만 나옴. 게임 150만원은 1안만 생성.
- 영향 범위: 모든 용도. 사용 가능 Intel CPU 58개, LGA1700/1851 보드 251개가 있어도 추천에서 제외됨.

#### 원인
- 확인된 원인과 근거:
  1. 카탈로그 전체 보드 중 CPU 지원(BIOS) 목록이 등록된 보드는 b1(MSI PRO B650M-A WIFI, AM5) 1개뿐이다. `validate`의 BIOS 지원 검사는 목록이 없으면 `null`(미확인)이고, 엔진은 미확인을 통과로 취급하지 않는다. 진단 스크립트 결과 Intel CPU×보드 8,368조합 전부 BIOS 지원 `null`이었다. 따라서 추천은 b1과 b1 목록의 AMD CPU 6종으로만 구성된다.
  2. 다나와 원문 표기 변형을 파서가 놓쳤다. CPU `인텔(1700소켓)` 표기(기존 정규식은 `소켓1700`만 인식), `PBP-MTP: 125~253W`·`TDP: 65~117W`의 물결·범위 표기, `UHD 770` 내장그래픽 표기를 놓쳤다. 보드 `[메모리] / 9066MHz (PC5-72500) / 4개 / 메모리 용량` 묶음의 슬롯 수도 놓쳤다. 그 결과 B860 보드 115개가 슬롯 미확인으로 사용 불가였고, 14700K·14600K(벌크+쿨러) 등이 소켓·전력 미확인이었다.
  3. 게임 강화안의 AMD X3D 우선 정책([srs.md](srs.md) 2026-11-06)은 의도된 동작이다. AMD 쏠림의 주원인은 아니다(원인 1이 해소된 가정 시뮬레이션에서 Intel이 균형·절약안에 다수 선택됨).
- 남은 가설: 없음.

#### 해결 방법
- 변경 또는 임시 조치와 적용 이유: `parseSpecs`가 `(1700소켓)` 표기, `-`/`~` 범위의 최대 전력, TDP 범위, UHD/Iris Xe 내장그래픽, `8+12코어` 하이브리드 표기를 인식한다. 보드 슬롯은 `[메모리]` 묶음 중간 항목을 건너뛰되 `메모리 용량` 바로 앞의 `N개`만 사용한다. 근거 없는 값은 계속 `null`로 둔다.
- 변경 파일·설정: `pipeline/adapters/danawa.mjs`, `tests/pipeline.test.mjs`.
- 원인 1(보드 BIOS 목록)은 미해결이다. ASRock(Incapsula 차단)·GIGABYTE·MSI(HTTP 403) 공식 지원 페이지가 자동 요청을 거부한다. 차단을 우회하지 않으며 미확인 지원을 추정 등록하지 않는다.

#### 재발 방지
- 적용한 방지책과 근거 경로: 실제 다나와 원문 문자열로 작성한 회귀 테스트 2건(`tests/pipeline.test.mjs`). 스레드 수(`16+12쓰레드`)를 코어 수로, 확장슬롯·SATA 개수를 메모리 슬롯 수로 오인하지 않는 음성 사례를 포함한다.
- [ ] 사람이 브라우저로 확인한 제조사 CPU 지원 목록을 근거로 LGA1700/LGA1851 주요 보드(예: B760M DS3H GEN5, B760M Pro RS/D5, B860M DS3H, B860M Pro-A)를 `reviews.json` `specOverrides`에 등록
- [ ] 다음 일일 수집 후 재파싱 값이 카탈로그에 반영됐는지 확인 (2026-11-06 19:49 시작 수집은 수정 전 파서로 실행 중)

#### 검증 결과
- 실제 실행한 재현·명령·테스트와 결과: 수정 전 신규 테스트 실패(소켓 `null`, 슬롯 `null`) 확인 후 수정해 통과. `npm test` 95개 통과. 캐시된 다나와 상품 원문 1,210건 재파싱 비교: 보드 슬롯 278·CPU 전력 21·소켓 6·TDP 19·내장그래픽 79건 신규 확보, 기존 값 삭제 0건, 변경 2건(14700K 코어 12→20, 14600K 8→14로 P+E 합계 정정).
- 시뮬레이션: 재파싱 값만 적용 시 추천은 여전히 전부 AMD. 보드 4종에 BIOS 목록이 있다고 가정하면(저장하지 않은 가정) 게임 150만원 i5-14400F/Ultra 5 225F/i5-12400F로 3안 생성, 게임 250만원 i5-12600KF/i5-14600KF/Ultra 5 250K Plus 선택. BIOS 목록이 남은 유일한 차단 요인임을 확인.
- 미확인 사항·남은 위험: 실제 카탈로그 반영은 다음 수집 이후. '개발 200만원' 요청은 수정 전후 모두 견적 0안이며 이번 원인과 별개로 미조사.

#### 2026-11-06 재발 보고: 사무용 요청도 AMD만 추천
- 재현: "조용한 사무용 PC, 엑셀과 POS, 100만 원" → 세 안 모두 AMD 9600X + MSI PRO B650M-A WIFI.
- 원인: 위 원인 1과 같다(지원 목록 보드 1개). 사무용은 추가로, 벤치마크가 있는 Intel CPU 32개(i5-14400·i3-14100 등)가 `igpu` 미확인이라 내장그래픽 필터에서 빠진다. 위 파서 수정(UHD 표기 인식)으로 재파싱하면 32개 모두 `igpu: true`가 된다. 카탈로그 반영은 다음 수집 이후다.
- 조치: 사용자 결정으로 live 모드 추천을 pcquote 엔진으로 전환했다([intent](intent/2026-11-06-pcquote-engine.md)). pcquote는 칩셋 세대 규칙을 쓰고 buildmate 재파싱 사양을 함께 가져온다.
- 검증: 데이터 사본으로 띄운 서버(live, pcquote 연결)에서 같은 요청 → 3안 모두 Intel(i7-14700K·i5-14600K·i7-13700 + B760M DS3H D4), 발행 차단 부품 없음, 0.4초(가격 갱신 불필요 시).
- 상태: pcquote 엔진 사용 시 해결. 내장 엔진(`RECOMMEND_ENGINE=buildmate`, demo)은 여전히 보드 BIOS 목록 등록 전까지 AMD 편중.

### 2026-11-06-pcquote-quote-save-rejected — pcquote 견적 저장이 호환성 오류로 거부됨

- 날짜: 2026-11-06
- 상태: 해결
- 관련 경로: 이전 `backend/server.mjs`(삭제), pcquote `backend/src/pcquote/screen.py` `validate_issue`

#### 증상
- 서버 통합 작업 중 코드 검토로 발견. pcquote 엔진 연동 상태에서 Intel 견적(B760 등)을 확정하면 저장 API가 422 "호환성 오류가 있습니다."를 돌려준다. 예산을 넘지만 +5% 안인 견적은 "허용 예산을 초과했습니다."로 거부된다.
- 영향 범위: pcquote 엔진이 고른 견적 중 보드 CPU 지원 목록이 없는 보드나 예산 초과분이 있는 견적 전부. 실제 운영 화면에서는 재현 전 발견.

#### 원인
- 견적 생성·교체는 pcquote로 옮겼지만 `POST /api/quotes`는 그대로 buildmate `validateBuild`(보드별 BIOS 목록, 미확인은 실패)와 `budgetLimit`(예산 100%)로 다시 검사했다.
- UI 테스트가 `/api/quotes`를 가짜 응답으로 대체해 놓쳤다.

#### 해결 방법
- 서버를 pcquote 하나로 합치면서 저장 검증을 pcquote 엔진의 `evaluate`(칩셋 세대 규칙, BIOS 업데이트는 경고)와 예산 +5% 상한으로 바꿨다.

#### 재발 방지
- pcquote `tests/test_api.py::test_issue_accepts_bios_update_boards`: BIOS 업데이트 경고가 있는 3안을 실제 저장 API로 저장한다. `test_issue_quote_validates_and_stores`: 가격 불일치 409, 버전 불일치 409, 예산 +5% 초과 422.

#### 검증 결과
- 위 테스트 통과. 실제 서버에서 사무용 100만원 균형안(i7-14700K + B760M DS3H D4, BIOS 확인 표시, 1,035,088원 > 예산) 저장 201 확인 후 삭제.

### 2026-11-07-stale-facts-from-live-refresh — 견적 시 가격 갱신이 제품 사양을 옛 값으로 되돌림

- 날짜: 2026-11-07
- 상태: 해결(구조 변경으로 원인 경로 제거)
- 관련 경로: 이전 `backend/refresh-prices.mjs`(삭제), `pipeline/store.mjs` `acceptProduct`, pcquote `service.py` `accept_price`

#### 증상
- Python 수집기 섀도 대조에서 발견. 11-06 일일 수집이 가격을 받은 뒤에도 일부 인기 제품(dw-103692572, dw-123993804, dw-14110475 등)의 `product_facts` 사양 출처가 11-04 값으로 남음. `updated_at`은 그날 밤 시각(12:35Z).
- 영향 범위: 견적에 자주 뽑혀 실시간 가격 갱신을 거친 제품. 갱신 이후 바뀐 사양·등록월·출처 카테고리가 카탈로그에 반영되지 않음.

#### 원인
- 이전 Node 서버의 견적 시 가격 갱신이 메모리에 있던 카탈로그 부품 레코드(옛 사양 포함)를 `acceptProduct`의 part로 넘겨, 일일 수집이 쓴 최신 사양을 덮어씀.

#### 해결 방법
- 서버 통합(2026-11-06)으로 Node 서버를 지움. pcquote 서버의 가격 갱신은 `parts`의 가격과 `price_observations`만 기록하고 `product_facts`(사양)는 건드리지 않음. 사양은 수집기만 씀.

#### 재발 방지
- pcquote `service.accept_price`는 사양을 쓰지 않음(코드 구조). 섀도 대조(`python -m pcquote.collector shadow`)가 이런 차이를 필드별로 보고함.

#### 검증 결과
- 섀도 대조에서 해당 6건의 Python 결과가 같은 날 원문을 다시 파싱한 값임을 확인. 전환 후 실제 일일 수집에서의 재확인은 미확인.

### 2026-11-07-ddr5-platforms-dropped-by-allocation — 고예산 게임 견적에서 AM5·LGA1851이 후보에서 빠짐

- 날짜: 2026-11-07
- 상태: 해결
- 관련 경로: pcquote `backend/src/pcquote/engine/recommend.py` `_search`, `platform_anchors`

#### 증상
- 사용자 보고: "게임pc에도 intel cpu만 추천". 400만 원 4K 게임 견적 3안이 모두 i9 + DDR4 보드(B760M DS3H D4). 인기 1위 9800X3D와 인기 1위 보드 B850M 박격포가 나오지 않음. 후보 192개가 모두 DDR4 플랫폼(LGA1700·AM4).
- 250만·150만·120만 원은 AM4 5600·인텔 12~14세대 + DDR4 보드.

#### 원인
- 엔진은 부품별 예산 비율 ±범위 안에서 후보를 찾고, ±100% 범위에서 3개 이상 조합이 모이면 범위를 더 넓히지 않는다. QHD 이상 게임은 메모리 32GB가 필수인데 2026-11 시세로 가장 싼 32GB DDR5가 566,100원, DDR4가 359,700원이다. 400만 원의 메모리 몫(276,500원)의 ±100%(553,000원) 안에는 DDR4만 있어, DDR5만 쓰는 AM5·LGA1851 조합은 점수 계산 전에 빠졌다.
- 처음에는 CPU 렌더링 점수가 주원인이라고 답했으나, CPU 점수를 뺀 실험에서도 결과가 바뀌지 않아 정정했다.
- 낮은 예산(250만 원 등)은 범위 안에 32GB가 없어 전체 후보로 넓혀지므로 AM5도 경쟁했고, 인기 점수는 가장 높았지만(0.95 대 0.85) DDR5 추가 비용만큼 그래픽카드가 낮아져 균형안 점수 0.800 대 0.804로 근소하게 짐. 이것은 결함이 아니라 현재 가중치의 결과다.

#### 해결 방법
- 메모리는 DDR 종류별, 보드는 소켓·DDR 조합별로 가장 싼 제품과 가장 인기 있는 제품을 비율 범위와 상관없이 후보에 넣는다(`platform_anchors`). 총액 ±5% 규칙은 그대로.

#### 재발 방지
- pcquote `tests/test_popularity.py::test_ddr5_platforms_stay_candidates_when_ddr5_ram_exceeds_the_ram_share`: DDR5 32GB가 메모리 몫 ±100% 밖인 시장에서 AM5·LGA1851 조합이 후보에 남는지 확인. 수정 전 코드에서 실패함을 확인.

#### 검증 결과
- `uv run pytest` 119개 통과. 실제 카탈로그 400만 원 4K: 울트라5 250K Plus + B860, 9800X3D + B850M 박격포, 7800X3D + B850M 박격포(모두 DDR5). 250만·150만·120만 원 결과는 변화 없음(위 가중치 결과). 사무용 100만 원 정상.

### 2026-11-07-budget-over-and-flat-prices — 150만 원 요청 견적이 모두 150만 원을 넘고 세 안 가격이 비슷함

- 날짜: 2026-11-07
- 상태: 해결(150만 원 QHD는 구조적 한계가 남음)
- 관련 경로: pcquote `backend/src/pcquote/engine/recommend.py` `recommend`·`_pick_plans`, `engine/requirements.py`, `screen.py` `budget_cap`

#### 증상
- 사용자 보고: "150만원 이하로 뽑아 달라고 했는데 모두 150만원 넘었어. 그리고 3가지 안 모두 비슷한 가격". 화면 합계 1,553,120원 / 1,566,230원 / 1,535,320원.
- 기대: 예산 이하, 세 안의 가격 차이가 분명함.

#### 원인
- 엔진이 예산을 "±5%"로 해석해 후보 총액을 예산의 95~105%로 제한했다(`BUDGET_BAND`). 상한이 157.5만 원이라 예산 초과 견적이 나왔고, 세 안이 같은 좁은 구간에서 골라져 가격이 비슷했다. 의도된 설계였으나 "이하" 요청과 맞지 않았다.

#### 해결 방법
- 예산을 상한으로 고정(`BUDGET_CEILING=1.0`, 발행 상한 `budget_cap`도 예산 그대로). 후보는 예산의 55% 이상(`POOL_FLOOR`).
- 성능 우선형은 균형형보다 12% 이상 비싸게(`STRONG_GAP`), 가성비형은 15% 이상 싸게(`CHEAP_GAP`) 고른다. 간격을 만족하는 조합이 없으면 순서만 지키고 간격을 줄여 제시하며 안내문에 남긴다.

#### 재발 방지
- pcquote `tests/test_recommend.py::test_plans_never_exceed_budget_and_are_priced_apart`, `test_plans_under_budget_ceiling`(예산 이하), 간격 기준을 쓰도록 고친 기존 테스트. 픽스처 의존 테스트 4건(`test_popularity` 2, `test_api`, `test_fallback_stays_near_budget`)은 새 규칙에 맞게 수정.

#### 검증 결과
- pcquote `uv run pytest` 125개, buildmate `npm test` 79개 통과.
- 실제 카탈로그(2026-11-07, 게임 QHD): 250만 원 → 200만/249만/150만 원, 400만 원 → 322만/384만/269만 원. 사무용 150만 원 → 131만/147만/93만 원. 모두 예산 이하.
- 한계(2026-11-07 재검증으로 정정): 처음에는 "게임 QHD 150만 원은 148.5만~149.8만 원으로 세 안이 붙는다"고 기록했으나, 조립비 0원으로 엔진만 돌린 결과였다. 실제 조립비 50,000원을 넣은 화면 경로에서는 최소 사양 견적이 1,535,320원(사용자 화면의 절약안과 같은 금액)이라 150만 원 QHD 게임 견적은 한 건도 나오지 않고 "최저 견적 1,535,320원" 안내만 표시된다. → 요청자 결정("2번으로 하고 안내를 하자")에 따라 최소 사양을 단계적으로 낮춰 견적을 내고 안내하도록 변경([intent](intent/2026-11-07-relax-min-specs.md)). 150만 원 QHD는 메모리 16GB로 낮춰 예산 이하 3안 제시.
- 재검증(화면 함수 `screen.recommend_fresh`, 가격 갱신 끔, 조립비 30,000원, 9개 조건): 모든 견적이 예산 이하, `budgetCap`=예산, 순서 위반·호환 오류 0건. 간격 충분: 게임 QHD 250만(1.12/0.77)·4K 400만(1.16/0.76)·편집 300만(1.13/0.78)·AI 200만(1.18/0.77). 간격 축소: 게임 FHD 150만(1.02/0.99)·사무 100만(1.04/0.98). 대체 경로 안내문의 "예산 ±5%" 문구와 죽은 85%·70% 단계를 정리.
- 미확인: 실행 중인 서버에는 재시작 전까지 반영되지 않음. 브라우저 확인 없음. 150만 원 QHD 추천 계산이 약 11초(250만 원은 약 4.5초)로 측정되었으며 변경 전과 비교하지 않았음.

### 2026-11-11 EXAONE 응답 형식 연결

- 증상: 직접 연결 기본 호출·요구 해석은 성공하나 일부 상담 답변은 JSON 파싱에 실패해 규칙으로 대체됐다. 초기에는 HTTP 429도 발생했다.
- 원인/확인 수준: EXAONE은 문서상 content 앞 줄바꿈을 반환할 수 있다. 기존 파서는 줄바꿈 뒤 코드펜스를 제거하지 못했고, 상담의 평문 지시와 별도 JSON 시스템 지시도 함께 전달되고 있었다. 개별 실패 응답 원문을 저장하지 않아 모든 실패의 원인을 확정하지는 않았다. 429의 세부 한도 원인은 미확인이다.
- 해결: 시스템 메시지를 하나로 합치고 끝에 JSON 출력 조건(평문은 answer 문자열 내부에 적용)을 명시. content를 strip한 뒤 코드펜스를 제거한다.
- 재발 방지/검증: EXAONE 전송·오류 시 같은 제공자 내 재시도·규칙 대체·JSON 지시 순서·선행 줄바꿈+코드펜스 테스트 6개 통과. 전체 백엔드 270개·화면 88개·빌드 통과. 실제 EXAONE JSON 답변 확인. 실행 서버 재시작 후 확인 결과는 intent 참고.
