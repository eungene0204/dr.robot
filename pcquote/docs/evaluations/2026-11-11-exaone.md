### FAIL E002 — 해석 결함(오류 대체 기본값)
실제 EXAONE 호출 두 번이 각각 60.1초 read timeout. _local이 확인 질문을 넣지만 parse_requirement의 용도 미인식 기본값 gaming을 유지해, 평가 경로에서 RTX 5060 Ti가 포함된 3안을 생성했다. 균형안 1,476,070원/강화안 1,483,440원/절약안 1,473,260원. 예산과 호환성은 맞지만 논문 작성 요청에 게임용 그래픽카드를 배정한 잘못된 견적이다.

재현 분리: 같은 문장에 timeout을 주입하면 detect_profile=None → _local profile=gaming/QHD + 용도 질문 반환을 재현한다. 따라서 단순 기대값 오류나 카탈로그 문제가 아니라, LLM 사용 불가 시 용도 불명 요청을 처리하는 기존 대체 경로의 해석 결함이다. 제품 수정은 미실행.

### 화면 45초 제한과 서버 처리시간 불일치 — 연결 결함
buildmate/src/main.jsx send는 요구 해석 fetch에 AbortSignal.timeout(45000)을 사용한다. EXAONE 서버 경로는 각 호출 최소 60초·최대 2회 재시도를 사용한다. 평가 하네스는 이 UI 제한을 실행하지 않는다.

대표 61턴 중 17턴에서 실제 LLM 호출 시간 합이 45초를 초과했다. 단독 후속에서도 E002 120.1초, E003 51.4초로 제한을 넘겼다. 따라서 하네스 PASS인 요청도 화면에서는 timeout으로 견적을 받지 못할 수 있다. 본 수치는 실제 하네스 호출 시간과 소스 제한의 비교이며 17건을 브라우저로 직접 재현한 결과는 아니다. API 제한 재현 결과는 아래에 기록한다.
