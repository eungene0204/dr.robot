# Intent: 예산 견적에서 항상 세 안 제시

- 작성일: 2026-11-06
- 요청자: 사용자
- 작성자: Claude Code
- 상태: 완료
- 요청자/제품 책임자 검토: 미검토

## 문제와 이유

'200만원 이하 adobe용 견적'처럼 균형안이 예산을 거의 다 쓰면(1,990,352원) 그보다 나은 구성이 예산 안에 없어 성능 강화안이 비어 있다. 균형안을 낮춰 강화안과 함께 고르는 공동 선택이 게임 용도에만 적용되어 편집·AI·사무 용도에서는 세 안이 나오지 않는다. 요청자는 항상 세 안을 원한다.

## 기대 결과

예산이 있는 요청에서 카탈로그에 조건을 만족하는 서로 다른 구성이 충분하면 균형안·강화안·절약안이 모두 나온다. 강화안은 균형안 대비 실제 개선(사양 비하향)이 있고, 절약안은 균형안보다 저렴하다.

## 영향받는 사용자와 시스템

상담 화면의 세 안 비교, POST /api/recommend/fresh, src/proposal-objectives.mjs의 selectProposals.

## 범위

- 포함: 강화안 또는 절약안이 비면 모든 용도에서 균형안 후보를 성능 순으로 다시 골라 세 안이 모두 성립하는 균형안을 선택한다. 예산 90% 이하 절약안이 없으면 균형안보다 저렴한 구성을 목표 미달(targetMet=false)로 표시해 제시한다.
- 제외: 예산 초과 허용, 개선 조건(사양 비하향·게임 CPU/GPU 향상) 완화.
- 추가(같은 날): 예산 없는 요청도 공동 선택을 적용한다. 이때 균형안은 최고 성능이 아닐 수 있으며 선택 기준을 '강화안·절약안이 함께 성립하도록 고른 성능 상위 구성'으로 표시한다.

## 제약

예산 상한, 호환성, 강화안의 비하향·개선 조건과 절약안의 가격 조건은 유지한다. 세 안을 위해 조건을 위반한 구성을 만들지 않는다.

## 수용 기준

- [x] 실제 카탈로그에서 '200만원 이하 adobe용 견적'이 세 안을 모두 반환한다.
- [x] 강화안은 균형안 대비 개선 내역이 1개 이상이고 예산 이하이다.
- [x] 기존 게임 공동 선택과 전체 테스트가 유지된다.

## 가정과 열린 질문

- 가정: 조건을 만족하는 서로 다른 구성 자체가 부족하면(예: 극저예산) 허위 견적을 만들지 않고 빈 안을 유지한다.
- 질문: 없음

## 구현 및 검증 결과

- 관련 코드·문서: src/proposal-objectives.mjs, tests/engine.test.mjs
- 수용 기준별 검증: 재시작한 실제 API(8001)에서 '200만원 이하 adobe용 견적' → 균형 1,848,212원(9600X·GTX 1660 SUPER) / 강화 1,940,212원(GPU → RTX 3060 12GB) / 절약 1,709,322원. 신규 단위 테스트 2개는 변경 전 코드에서 실패, 변경 후 통과. 전체 테스트 85개 통과. 실제 카탈로그(가격 유효 가정) 4개 용도×6개 예산 점검에서 구성이 가능한 모든 경우 세 안 생성.
- 남은 항목: 예산이 최소 구성 미만이거나 서로 다른 유효 구성이 부족한 경우(예: AI 200만원, 데모 카탈로그 게임 150만원)는 허위 견적 없이 빈 안을 유지한다. 공동 선택 시 균형안이 처음보다 낮은 성능으로 바뀔 수 있다.
